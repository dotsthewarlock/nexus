Technical limits and interpretation


Iframe API: allow="autoplay" delegates permission but does not command a third-party player to start. Synthetic clicks on the iframe DOM node do not target the embedded Play button. Access to contentWindow.document should be rejected by same-origin restrictions.


Dacast JS API: Its documented onReady(), muteOn(), play() and onPlay() methods offer a genuine control route if the operator permits this embedding mode. The API Play diagnostic is always enabled during E/F tests, but it cannot control a player that has not initialized. A failure to reach onReady() is reported separately from playback failure.


Not attempted: stream extraction, relaying, forged referrers, hidden browser automation, guessed private postMessage commands or bypassing Dacast publisher restrictions.


Sources: Dacast Player JS API · Dacast autoplay guide · Same-origin policy
